# mac-cleaner

Быстрый и безопасный CLI-инструмент для освобождения дискового пространства в macOS.

[English](../README.md) | [Polski](README_PL.md) | [Deutsch](README_DE.md) | [Українська](README_UA.md) | Русский | [Français](README_FR.md)

## Возможности

### Системные кэши
- **Кэш приложений** — `~/Library/Caches/` (безопасно). Папки кэша, которые охватывает отдельный флаг, не включаются, поэтому пропуск или сохранение этого пункта защищает и его данные: `com.apple.Safari` (`--safari`), `Google/Chrome` (`--chrome`), `Firefox` (`--firefox`), `yarn` (`--yarn`), `Homebrew` (`--homebrew`), `CocoaPods` (`--cocoapods`), `pip` (`--pip`), `Adobe` (`--adobe`), `com.bohemiancoding.sketch3` (`--sketch`), `com.microsoft.teams2` (`--teams`).
- **Логи пользователя** — `~/Library/Logs/` (безопасно)
- **Миниатюры QuickLook** — кэш QuickLook пользователя (безопасно)

### Данные браузеров
- **Кэш Safari** — `~/Library/Caches/com.apple.Safari/` (умеренный риск)
- **Кэш Chrome** — `~/Library/Caches/Google/Chrome/` для всех профилей (умеренный риск)
- **Кэш Firefox** — `~/Library/Caches/Firefox/` (умеренный риск)

### Кэши разработчика
- **Xcode DerivedData** — `~/Library/Developer/Xcode/DerivedData/` (рискованно)
- **Кэш npm** — `~/.npm/` (умеренный риск)
- **Кэш Yarn** — `~/Library/Caches/yarn/` (умеренный риск)
- **Кэш Homebrew** — `~/Library/Caches/Homebrew/` (умеренный риск)
- **Docker — освобождаемые ресурсы** — контейнеры, образы, кэш сборки, тома (рискованно)
- **Кэш симулятора iOS** — `~/Library/Developer/CoreSimulator/Caches/` (безопасно)
- **Логи симулятора iOS** — `~/Library/Logs/CoreSimulator/` (безопасно)
- **Xcode Device Support** — `~/Library/Developer/Xcode/iOS DeviceSupport/` (умеренный риск)
- **Xcode Archives** — `~/Library/Developer/Xcode/Archives/` (рискованно)
- **Хранилище pnpm** — `~/Library/pnpm/store/` (умеренный риск)
- **Кэш CocoaPods** — `~/Library/Caches/CocoaPods/` (умеренный риск)
- **Кэш Gradle** — `~/.gradle/caches/` (умеренный риск)
- **Кэш pip** — `~/Library/Caches/pip/` (безопасно)

### Кэши проектов
- **node_modules** — каталоги `node_modules/` в проектах JavaScript/TypeScript (безопасно)
- **.build (Swift)** — каталоги `.build/` в проектах Swift Package Manager (безопасно)
- **target (Rust)** — каталоги `target/` в проектах Cargo/Rust (безопасно)
- **venv (Python)** — каталоги `venv/` и `.venv/` в проектах Python (умеренный риск)
- **build (Java/Kotlin)** — каталоги `build/` рядом с `build.gradle` или `build.gradle.kts` в проектах Gradle (безопасно). Каталог `build/` рядом только с `pom.xml` не отмечается: Maven записывает результаты сборки в `target/`, поэтому `build/` там обычно содержит написанные вручную файлы.

Кэши проектов обнаруживаются путём обхода домашнего каталога и валидации каждого кандидата по файлу манифеста (например, `package.json` для node_modules, `Cargo.toml` для target). Проекты, неактивные более 6 месяцев, отмечаются индикатором неактивности.

### Файлы домашнего каталога
- **Большие файлы (>100 МБ)** — файлы больше 100 МБ в домашнем каталоге (рискованно)
- **Старые файлы (>180 дней)** — файлы старше 180 дней и больше 10 МБ в домашнем каталоге (рискованно)

Сканирование домашнего каталога исключает `~/Library`, `~/Applications`, `~/.Trash`, `~/Downloads` и каталоги с точкой (например, `~/.config`). Результаты отмечаются как "рискованные", так как это личные файлы, а не восстановимые кэши. Сканирование также никогда не заходит в пакеты и библиотеки macOS (`.photoslibrary`, `.musiclibrary`, `.tvlibrary`, `.imovielibrary`, `.fcpbundle`, `.logicx`, `.app`, `.bundle`, `.framework`, `.sparsebundle`, `.pvm`, `.vmwarevm`, `.utm`), метаданные систем контроля версий (`.git`, `.hg`, `.svn`), установленные инструменты (`~/bin`, `~/go/bin`) и медиатеки Музыки и TV (`~/Music/Music`, `~/Movies/TV/Media.localized`): удаление одного файла внутри повреждает всю библиотеку, репозиторий или установку. Пороговые размеры сравниваются с фактически занятым местом на диске, поэтому разреженный файл (например, образ диска VM), занимающий мало места, не считается большим.

> **Примечание:** Файлы-заполнители iCloud Drive могут показывать оригинальный размер, даже если они удалены из локального хранилища.

### Очистка Git-репозиториев
- **Git-репозитории** — каталоги `.git/`, найденные в домашнем каталоге (умеренный риск)

Очистка Git-репозиториев обнаруживает каталоги `.git` в вашем домашнем каталоге, показывает их размер и оценку освобождаемого пространства через `git count-objects`, и предлагает очистку `git gc --aggressive`. Для репозиториев с Git LFS (обнаруженных через `.git/lfs`) автоматически запускается `git lfs prune`, если `git-lfs` установлен. Репозитории с активными операциями (наличие `index.lock`) безопасно пропускаются, как и репозитории, в которых нечего перепаковывать (оценка 0 B). Перед запуском `git gc` очистка повторно проверяет каждый репозиторий и пропускает его, пока существует `index.lock` или `gc.pid`.

> **Примечание:** Очистка запускает `git gc --aggressive` и `git lfs prune`. Файлы рабочего каталога не удаляются, но `git gc` перепаковывает объекты и также удаляет недостижимые объекты старше срока хранения git (например, отброшенные stash), а `git lfs prune` удаляет старые локальные копии LFS. Итог очистки показывает измеренное уменьшение `.git`, а не оценку сканирования.

### Остатки приложений
- **Осиротевшие настройки** — файлы `.plist` в `~/Library/Preferences/` для удалённых приложений (рискованно)
- **Резервные копии устройств iOS** — `~/Library/Application Support/MobileSync/Backup/` (рискованно)
- **Старые загрузки** — файлы в `~/Downloads/` старше 90 дней (умеренный риск)

Осиротевшие настройки никогда не включают системные домены macOS (имена без точки в стиле reverse-DNS, например `loginwindow`, файлы с точкой, например `.GlobalPreferences`, всё, что содержит `com.apple.`, `systemgroup.*` и `org.cups.PrintingPrefs`) и файлы `.plist`, изменённые за последние 90 дней. Установленные приложения распознаются по собственному идентификатору пакета и по идентификаторам вложенных в них вспомогательных приложений, объектов входа и расширений, в том числе для приложений в `/Library/Application Support`. Если идентификатор пакета любого установленного приложения не удаётся прочитать, в этом запуске осиротевшие настройки не сообщаются. Папка в `~/Downloads` считается старой, только если за последние 90 дней в ней ничего не менялось; папки, слишком глубокие или большие для полной проверки, не трогаются.

## Безопасность

mac-cleaner разработан для защиты вашей системы:

- **SIP-защищённые пути заблокированы** — `/System`, `/usr`, `/bin`, `/sbin` никогда не затрагиваются (`/usr/local` разрешён)
- **Защита swap/VM** — `/private/var/vm` всегда заблокирован для предотвращения паники ядра
- **Разрешение символических ссылок** — все пути разрешаются перед удалением
- **Три уровня риска** — каждая категория классифицируется как **безопасная**, **умеренная** или **рискованная**
- **Повторная валидация перед удалением** — проверки безопасности выполняются снова во время удаления, а не только при сканировании
- **Режим предварительного просмотра** — просмотр всего перед выполнением с `--dry-run`
- **Интерактивное подтверждение** — требуется явное согласие пользователя перед удалением (если не используется `--force`)

Подробный анализ безопасности см. в документе [Архитектура безопасности](SECURITY_RU.md).

## Использование

**Интерактивный режим** (по умолчанию — проводит по каждой категории):
```bash
./mac-cleaner
```

**Сканировать всё, только предварительный просмотр:**
```bash
./mac-cleaner --all --dry-run
```

**Очистить системные кэши без подтверждения:**
```bash
./mac-cleaner --system-caches --force
```

**Сканировать всё, вывод в JSON:**
```bash
./mac-cleaner --all --dry-run --json
```

**Сканировать всё, но пропустить Docker и резервные копии iOS:**
```bash
./mac-cleaner --all --skip-docker --skip-ios-backups
```

**Сканировать кэши сборки проектов (node_modules, .build, target, venv, build):**
```bash
./mac-cleaner --project-caches --dry-run
```

**Сканировать большие и старые файлы в домашнем каталоге:**
```bash
./mac-cleaner --home-files --dry-run
```

**Сканировать Git-репозитории на предмет освобождаемого кэша:**
```bash
./mac-cleaner --git-repos --dry-run
```

**Сканировать только каталоги node_modules:**
```bash
./mac-cleaner scan --node-modules --dry-run
```

**Точечное сканирование — только определённые элементы (через подкоманду `scan`):**
```bash
./mac-cleaner scan --npm --safari --dry-run
```

**Точечное сканирование — целая группа плюс отдельные элементы:**
```bash
./mac-cleaner scan --dev-caches --safari
```

**Точечное сканирование — группа за вычетом определённых элементов:**
```bash
./mac-cleaner scan --dev-caches --skip-docker
```

**Структурированная справка для AI-агентов:**
```bash
./mac-cleaner --help-json
```

### Итоги и сводка очистки

Каждая строка `Total: X reclaimable` показывает, что очистка фактически удаляет, при этом каждый путь учитывается один раз. Если это отличается от всего, что учло сканирование, далее указывается учтённая сумма, например `Total: 0 B reclaimable (76.8 GB counted, see --verbose)`. Учтённые, но не удаляемые байты включают неиспользуемые приложения в `/Applications` (заблокированные проверкой безопасности) и их данные в `~/Library`, записи Docker и Time Machine, git-репозитории (очистка запускает `git gc` вместо удаления файлов) и пути, которые перечисляет более одной категории. Сводка dry-run показывает для каждой категории байты, которые удаляет очистка, отсортированные по этому размеру.

Перед удалением запрос подтверждения перечисляет, что будет удалено безвозвратно (с числом удаляемых байтов), какие репозитории перепакует `git gc` (с оценкой), и что перечислено, но не удаляется (записи Docker и Time Machine, заблокированные бандлы и оставляемые данные, например данные неиспользуемого приложения в `~/Library`). Его итог — это то, что будет удалено.

После очистки `Cleanup complete: N items removed, X freed` показывает фактически освобождённые байты: каждый удалённый путь один раз плюс измеренное уменьшение каждого каталога `.git`. Элементы, в которых нечего удалять (записи Docker и Time Machine, уже удалённые или отсутствующие пути, занятые git-репозитории), отмечаются как пропущенные, отдельно от ошибок.

С `--json` вывод сохраняет `total_size` (всё учтённое) и добавляет `unique_size` (учтённое, каждый путь один раз) и `removable_size` (что удаляет очистка); каждая категория также получает `removable_size`. Используйте `--json` вместе с `--dry-run` для вывода только сканирования. Без `--dry-run` `--json` переходит к очистке, а запрос подтверждения и итог очистки выводятся в stderr, поэтому stdout остаётся одним JSON-документом.

### Подробная разбивка размеров

С `--verbose` каждая запись показывает свой путь. Если размер записи включает больше, чем этот путь, или очистка не удалит его, запись также перечисляет каждый учтённый путь с его размером (от большего к меньшему). Пути, которые очистка не удаляет, помечены `(counted, not removed by cleanup)`, а строка `cleanup removes X of Y counted` появляется, когда значения различаются. Примеры: неиспользуемые приложения (бандл плюс данные в `~/Library`), Docker (оценка из `docker system df`), git-репозитории (оценка из `git count-objects`; очистка запускает `git gc`) и снимки Time Machine (размер недоступен).

В конце запуска с `--verbose` раздел `Counted More Than Once` перечисляет каждый путь, учтённый более чем одной записью: тот же файл среди больших и старых файлов или путь, вложенный в путь другой категории (например, кеш Chrome в `~/Library/Caches/Google`, который также учитывает категория кешей приложений). Он показывает, какие категории его учитывают, сумму, где каждый байт учтён один раз, и сколько удалит очистка, если каждый путь учесть один раз. Раздел появляется, только если такие пути есть среди просканированных (и не пропущенных) категорий.

```
      Docker (last used Dec 2024)  [risky]    71.4 GB
        /Applications/Docker.app
            68.8 GB  ~/Library/Containers/com.docker.docker  (counted, not removed by cleanup)  - app data in ~/Library
             2.6 GB  /Applications/Docker.app  (counted, not removed by cleanup)  - app bundle; cleanup is blocked by safety check: outside home directory
          cleanup removes 0 B of 71.4 GB counted
```

Размеры — это место, фактически выделенное на диске (как показывает `du`), причём файлы с жёсткими ссылками учитываются один раз, в единицах SI (1 GB = 10^9 байт, как в Finder). `du -h` использует единицы на основе 1024, поэтому числа немного различаются. Клоны APFS по-прежнему учитываются в полном размере. Размеры для Docker и git являются оценками. В выводе `--json` та же разбивка доступна как необязательный массив `components` у каждой записи.

### Подкоманда scan

Подкоманда `scan` обеспечивает точечное сканирование на уровне отдельных элементов. В отличие от основной команды (которая по умолчанию запускает интерактивный режим), `scan` требует явного указания флагов и поддерживает выбор конкретных элементов.

```bash
# Сканировать только кэши npm и yarn
mac-cleaner scan --npm --yarn --dry-run

# Сканировать все кэши разработчика плюс Safari
mac-cleaner scan --dev-caches --safari

# Сканировать всё, кроме Docker
mac-cleaner scan --all --skip-docker

# Вывод в JSON для автоматизации
mac-cleaner scan --npm --json --dry-run
```

Выполните `mac-cleaner scan --help` для полного списка флагов точечного сканирования, сгруппированных по категориям.

## Очистка по расписанию

`mac-cleaner schedule` устанавливает пользовательский агент launchd (`~/Library/LaunchAgents/com.mac-cleaner.plist`), который автоматически очищает кэши разработчика — по умолчанию Xcode DerivedData, каждую ночь в 03:00. Агент работает от имени вашего пользователя, поэтому `sudo` не требуется.

```bash
# Очищать Xcode DerivedData ежедневно в 03:00
mac-cleaner schedule install

# Также очищать кэши симулятора iOS, в 22:30 по понедельникам и пятницам
mac-cleaner schedule install --at 22:30 --weekdays mon,fri --simulator-caches

# Предпросмотр без установки
mac-cleaner schedule install --dry-run

mac-cleaner schedule status      # расписание, следующий запуск, последний код выхода, путь к журналу
mac-cleaner schedule run         # запустить задачу сейчас
mac-cleaner schedule uninstall   # удалить агент
```

| Флаг | Описание |
|------|----------|
| `--at HH:MM` | Время запуска в 24-часовом формате (по умолчанию `03:00`) |
| `--weekdays` | Дни через запятую, например `mon,wed,fri` (по умолчанию каждый день) |
| `--targets` | Элементы кэша для очистки, по именам флагов `scan` (по умолчанию `derived-data`). Рискованные элементы и элементы с данными пользователя отклоняются (см. ниже) |
| `--simulator-caches` | Также очищать кэши симулятора iOS |
| `--even-if-running` | Очищать, даже если Xcode запущен (по умолчанию запуск пропускается) |

Примечания:
- Если Mac спит в запланированное время, задача выполнится после пробуждения; если он выключен, этот запуск пропускается.
- Вывод дописывается в `~/Library/Logs/mac-cleaner/scheduled.log`.
- Повторный `install` заменяет существующее расписание. При установке через Homebrew используется стабильный путь `/opt/homebrew/bin/mac-cleaner`, поэтому обновления не нарушают работу.
- Поскольку запуски по расписанию удаляют без подтверждения, `install` отклоняет рискованные цели и цели с данными пользователя, например `large-files`, `old-files`, `orphaned-prefs`, `old-downloads`, `ios-backups`, `mail`, `messages`, `xcode-archives`, `docker` и цели виртуальных машин. `derived-data` — единственное исключение с уровнем «рискованно», так как Xcode создаёт его заново.
